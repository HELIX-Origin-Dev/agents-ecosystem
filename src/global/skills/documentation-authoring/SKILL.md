---
name: Documentation Authoring
description: Write maintainable documentation with one canonical home for each technical fact.
---

## Goal

Help readers find accurate answers quickly without maintaining duplicate explanations.

## When to use

- Creating or updating user-facing or developer documentation.
- Adding a diagram, table, or procedure to an existing page.
- Consolidating repeated facts found across several documents.

## Steps

1. Identify the audience and the question the page must answer.
2. Place each technical fact in one canonical module and link to it elsewhere.
3. Choose a clear structure with headings, tables, and short status labels.
4. Use diagrams when a flow, sequence, state, or relationship benefits from one.
5. Keep examples portable and replace all sensitive values with `<VALUE>`.
6. Use consistent dates and real links; avoid unpublished version claims.
7. Review the page from the perspective of a reader who has no prior context.

## Verification

- Every link resolves and every example works as written.
- No fact is duplicated in a way that could drift out of sync.
- The page contains no local machine paths or sensitive values.
